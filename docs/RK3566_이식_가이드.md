# Raspberry Pi 5 → RK3566 이식 가이드

`python/` 센서 브리지(ToF·NFC·마이크 → Unity UDP)는 보드 하드코딩(GPIO 번호, I2C 버스/주소,
ALSA 카드 번호 등)이 전부 [`python/hardware_config.yaml`](../python/hardware_config.yaml) 로
분리되어 있습니다. **RK3566 커스텀 보드로 옮길 때 `python/*.py` 코드는 건드릴 필요가 없고**,
이 YAML 파일과 배선만 맞추면 됩니다.

## 무엇이 바뀌었나 (RPi 전용 → Linux 표준 API)

| 구분 | 이전 (RPi 전용) | 이후 (Linux 표준, 보드 공용) |
|---|---|---|
| I2C | `board`/`busio` (Blinka, RPi 핀 매핑에 의존) | `smbus2` — `/dev/i2c-N` (커널 i2c-dev, 모든 Linux 보드 공용) |
| GPIO | `RPi.GPIO` (RPi 전용, deprecated) | `gpiod` (libgpiod, `/dev/gpiochipN` — 커널 표준 char-device API) |
| 하드코딩 값 | 각 `.py` 파일에 상수로 박혀 있었음 | `python/hardware_config.yaml` 한 곳에서 관리 |

`adafruit-circuitpython-vl53l0x`/`adafruit-circuitpython-pn532` 드라이버는 그대로 재사용합니다 —
`python/hardware/i2c_bus.py` 의 `LinuxI2CBus` 가 `busio.I2C` 와 동일한 메서드
(`try_lock`/`unlock`/`writeto`/`readfrom_into`/`scan`)를 `smbus2` 로 구현해서
드라이버 입장에서는 RPi인지 RK3566인지 구분하지 않습니다.

## 이식 절차

### 1. 하드웨어 확인 (RK3566 보드에서)

```bash
i2cdetect -l                 # I2C 버스 번호 확인 (예: i2c-3)
i2cdetect -y <bus>           # 0x29(VL53L0X), 0x24(PN532) 주소 배선 확인
gpiodetect                   # GPIO 칩 이름 확인 (예: gpiochip1) — GPIO 실제 사용 시만
gpioinfo <chip>              # 라인 번호(offset) 확인 — GPIO 실제 사용 시만
arecord -l                   # 마이크(I2S/USB) ALSA 카드 번호
```

### 2. 패키지 설치

```bash
sudo apt install -y python3-pip portaudio19-dev alsa-utils i2c-tools gpiod libgpiod2
pip install -r python/requirements-pi.txt
```

`adafruit-blinka`(Pi 전용 Blinka)는 더 이상 필요 없습니다 — `smbus2`/`gpiod` 로 대체되었습니다.

### 3. `python/hardware_config.yaml` 수정

```yaml
active_board: rk3566   # 또는 환경변수 HARDWARE_BOARD=rk3566 로 override

boards:
  rk3566:
    i2c:
      bus: 3            # 위 i2cdetect -l 로 확인한 번호
    gpio:
      chip: gpiochip1   # gpiodetect 로 확인한 이름 (GPIO 안 쓰면 무시해도 됨)
    audio:
      alsa_card: "0"    # arecord -l 로 확인한 번호
    display:
      env:
        DISPLAY: ":0"
        XAUTHORITY: "/home/root/.Xauthority"   # 실제 로그인 계정 홈으로 수정
```

I2C 주소(`common.i2c.vl53l0x_address`/`pn532_address`), 터치/근접 거리 임계값
(`common.distance.*`), 마이크 임계값(`common.voice.*`), UDP 포트(`common.network.*`) 등은
보드 공통값이라 보통 그대로 두면 되지만, 보드마다 다르면 `boards.rk3566` 아래에
같은 키를 추가해 override 할 수 있습니다.

### 4. 점검

```bash
export HARDWARE_BOARD=rk3566   # active_board 를 안 바꿨다면 이렇게 override
python3 python/sensor_check.py
```

`i2cdetect -y <bus>` 결과와 VL53L0X 5회 측정, 마이크 장치 목록이 출력됩니다.
문제 없으면 기존과 동일하게 실행합니다:

```bash
python3 python/eternal_beam_pi.py --simulate      # 배선 없이 로직만 테스트
UDP_HOST=<Unity 폰 IP> python3 python/eternal_beam_pi.py
```

### 5. systemd 자동 실행

`python/systemd/eternal-beam-pi.env` 에 `HARDWARE_BOARD=rk3566` 한 줄만 추가하면
서비스 파일은 그대로 재사용할 수 있습니다. 나머지는
[`python/systemd/README.md`](../python/systemd/README.md) 참고.

## GPIO(선택) — 상태 LED/버튼 등을 실제로 연결하는 경우

현재 조립본은 GPIO 라인을 쓰지 않습니다(`hardware_config.yaml` 의 `gpio.lines.*.enabled: false`).
LED나 버튼을 실제로 연결하면:

1. `gpioinfo <chip>` 으로 사용할 라인의 offset 확인
2. `hardware_config.yaml` 의 `common.gpio.lines.status_led` (또는 새 라인 추가) 에
   `enabled: true`, `offset: <숫자>` 설정
3. 코드에서는 `python/hardware/gpio.py` 의 `open_line("status_led")` 만 호출하면 됨
   (`eternal_beam_pi.py` 에 이미 사용 예시가 있음) — `gpiod`/하드웨어가 없으면 자동으로
   `None` 을 반환하므로 미조립 상태에서도 에러 없이 동작합니다.

## 코드에서 새로 알아야 할 것

- `python/hardware/config.py` — `hardware_config.yaml` 로더 (`load_hardware_config()`)
- `python/hardware/i2c_bus.py` — `get_i2c_bus()` (smbus2 기반, `busio.I2C` 호환 shim)
- `python/hardware/gpio.py` — `open_line(name)` (libgpiod v1/v2 자동 감지)

새 센서를 추가할 때도 `board`/`busio`/`RPi.GPIO` 를 직접 import 하지 말고
이 세 모듈을 통해 접근하면, 다음 보드 이식 때도 `python/*.py` 를 다시 고치지 않아도 됩니다.
